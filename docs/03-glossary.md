# Small glossary
**Project / repository:** the folder containing an application's code and supporting files. A Git repository also tracks version history.
**Git:** local version history. **GitHub:** a hosting and collaboration service. They are not the same thing.
**Terminal:** an application where you type commands. **Command:** an instruction run by your computer.
**Model:** the system generating responses. **Coding agent:** a model working through a tool-equipped loop that may read files, edit and run checks.
**Prompt:** your request and context. **Context:** the information available for the current task, not necessarily everything the agent could discover.
**Acceptance criterion (AC):** an observable rule used to judge a result.
**State:** the application's current data, such as XP and completed quests.
**Function:** a named piece of behavior, such as completeQuest.
**UI:** the user interface you see and operate.
**Test / check:** a repeatable observation against an expected result. **Regression:** previously working behavior that a change breaks.
**Diff:** the differences between versions of files.
**Test-driven development (TDD):** a short cycle of a failing test for a behavior, minimal implementation, and refactoring with tests still passing.
**Subagent:** a separately delegated agent task. Review a subagent’s findings before using them.
**MCP:** a protocol for connecting tools/context to model applications; not required for the exercises.
**Tool request versus permission:** the model can ask for an action; the application should decide whether it is allowed.
